**Title (the message):**
**One clear action replaces a choice people kept getting wrong**

Or, if you prefer a plainer one: "Parcelbox pickup: from two competing options to one obvious one."

**Visual:** Your two screenshots side by side at the same width and the same crop. Label them "Before" and "After" above each. Nothing else competes with them.

Pin short callouts to the spots on each screenshot, so the room doesn't have to hunt for the difference:
- **Before**, on the 12-digit pad: "12-digit code pad". On the QR option: "QR scanner, equal weight". Optionally, across both: "Two ways in, no clear first choice".
- **After**, on the big target: "One primary action". On the link: "Code entry, demoted to a link".

**One supporting line under the screenshots:**
"People often didn't know whether to type the code or scan it. Now the screen leads with scanning, and typing is a fallback."

That's the whole slide. Don't add a metrics panel, a process recap, or a bullet list. The screenshots carry it.

**Speaker notes (about 30 to 45 seconds):**

"This is the collect-your-parcel screen on the Parcelbox kiosk. Before, we gave people a 12-digit code pad and a QR scanner side by side, with roughly equal weight. We saw that people often didn't know which to use, and that hesitation is the problem we were solving.

The change is one decision: pick the primary path and commit to it. Scanning is now a big target that fills the screen. Typing the code is still there as a small 'Enter code instead' link, so nobody is locked out if they can't scan, for example if the QR code is on a dead phone or a printed slip that's damaged.

We don't have usage data from the kiosks yet, so I can't tell you how much this improves completion or time at the kiosk. What I can say is what the screen now asks of someone: one obvious action, instead of a choice. [Optional: say what you'll measure and when, e.g. 'we'll compare completion rate and time-to-collect once the kiosks report data.']"

**Notes on what I left out, and why:**
- **No numbers.** Anything like "X% faster" would be invented. Saying plainly that data isn't in yet reads as more credible to design leads than a vague claim, and it sets up a question you can answer.
- **No "users loved it" type claim.** Only use one if you have a real quote or observation. If you watched people hesitate in testing or on-site, say that in the notes: "[observation: where you saw the confusion, and how many people]".
- **The fallback matters.** Design leads will likely ask what happens if scanning fails. Having "Enter code instead" explained in your notes pre-empts that.
