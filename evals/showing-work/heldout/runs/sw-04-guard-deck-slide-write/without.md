# Before/after slide for Parcelbox

## Title
**One clear action instead of two competing ones**

The title states the design decision, so the leads get the point before they look at the screenshots. If your team prefers descriptive titles, use "Parcelbox pickup screen: before and after".

## Layout
Two screenshots side by side, with "Before" on the left and "After" on the right. Give them equal size so the comparison is fair.

**Labels above each screenshot**
- Before: **Two ways in, no clear starting point**
- After: **One primary path, one fallback**

**Short callouts under each screenshot** (2–3 per side, ideally with thin lines pointing at the screen)

Before:
- 12-digit code pad
- QR scanner option
- Users often unsure which to use

After:
- Large "Scan your QR code" target
- Small "Enter code instead" link

**Bottom line (one sentence, full width)**
> We made the most common path the obvious one and kept the other available without competing for attention.

Only include the words "most common path" if you know QR is the main route. If you don't, use "the path we want most people to take."

## Speaker notes
"This is the collect-your-parcel screen on the kiosk touchscreen. Before, we showed a 12-digit code pad and a QR scanner option at the same time. Both looked equally important, so people often didn't know which to use. That hesitation happens at the start of the task, when the person is standing at the kiosk with a parcel waiting.

For the redesign, we picked one primary action. The screen now shows a big 'Scan your QR code' target. Typing a code is still possible through a small 'Enter code instead' link, so nobody is locked out if their QR won't scan or they only have the code.

I don't have kiosk usage data yet, so I'm not claiming a measured improvement. This is a design decision based on [what you observed: user feedback, testing, or staff reports. Fill in whatever is true]. Once the kiosks are live, I plan to track [e.g. time to collect, how often people use the code fallback, abandoned sessions] to check whether it works.

I'd welcome your thoughts on the fallback link. Is it prominent enough for someone whose QR won't scan?"

## Notes
- **Fill in the evidence line.** The claim that people often didn't know which to use needs a source, such as observation, support complaints or a usability session. Name it in the notes, because design leads will probably ask.
- **Don't add numbers or "improved" claims.** The honest framing is a reasoned design change with a measurement plan. Leads usually respond better to that than to an unsupported claim.
- **The closing question about the fallback link is optional.** It invites useful feedback and it's the weakest point in the design, so it's better to raise it yourself.
