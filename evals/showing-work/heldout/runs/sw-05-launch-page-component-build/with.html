Time Slot Picker Stable · v2.1

A grid of selectable appointment times, grouped by day, for the Lumen Health patient scheduling app. It replaces the Dropdown Time Select.

  • Arrow-key navigation
  • Selection announced to screen readers
  • Empty state offers the next date with openings
  • Comfortable and compact densities

Patients used to pick a time from one long dropdown, with no sense of which days had room. The Time Slot Picker shows the days and their times together, so people can compare options before choosing.

On this page: Keyboard · Screen readers · Empty state · Density · Using it · Limits and open items

Arrow keys move through the grid like it looks

The grid is one tab stop. Inside it, left and right move between times, and up and down move to the nearest time in the row above or below, including across days. Focus follows the layout on screen, whatever the width.

Keys

← → previous or next time. ↑ ↓ nearest time in the adjacent row. Home End first or last time. Enter / Space select.

Try it above

Click once in the demo, press Tab to enter the grid, then resize the window. The up and down keys follow the new row breaks.

Selection is spoken, not only colored

Selecting a time updates a polite live region with the full day and time, for example “Selected Tuesday, November 3 at 10:30 AM.” Each time is a toggle button with a pressed state, so the selection never relies on color alone. The same text shows in the box under the grid.

An empty week points to the next opening

When no times are available, the picker says so and offers a button for the next date that has openings. Choosing it loads that date and moves focus to its first time. People are not left at a dead end.

See it

Switch the scenario in the demo to “No times,” then use the button in the empty state.

Behavior

The next-opening date comes from the data you pass in. The component displays it and does not search for it.

Two densities for two amounts of room

Comfortable has 44px-tall targets for the main booking flow. Compact has 32px-tall targets for tighter surfaces. Both keep the same behavior, order and labels, so switching changes size only, and your selection is kept.
