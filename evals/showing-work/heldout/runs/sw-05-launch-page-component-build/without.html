What it does

Keyboard arrow navigation

The grid is a single tab stop. Arrow keys move between times, including across day groups, so people don't tab through every slot.

Announces selection

Choosing a time updates a polite live region, so screen reader users hear the day and time they picked.

Empty state with a next step

When nothing is open, the picker says so and offers the next date with openings instead of leaving a blank area.

Two densities

Comfortable for patient-facing flows and touch. Compact for tighter layouts where space is limited.

Density

Both densities share the same behavior, markup, and accessibility semantics. Only spacing and size change.

Comfortable (default)
  • 44px tall targets
  • Use in patient-facing and mobile flows
Compact
  • 32px tall targets, smaller type
  • Use where vertical space is constrained, such as side panels

Keyboard and screen reader behavior

The picker is a radio group: one time can be selected at a time. Focus uses a roving tab stop, so Tab enters the grid once and leaves it once.

Guidance

Use it when

  • People choose one appointment time from a known set of openings.
  • Seeing several times at once helps them compare options.
  • You need to support keyboard and screen reader users equally well.

Don't use it when

  • The person is choosing a date. Pair the picker with a date control instead.
  • The user must enter an arbitrary time. Use a time input.
  • You would hide the empty state. Always let people know why nothing is shown.

Migrating from Dropdown Time Select

The Time Slot Picker replaces the Dropdown Time Select for choosing appointment times. Times are now visible at once instead of hidden in a menu, and selection is announced to assistive tech. Swap the component, choose a density, and make sure your flow handles the empty state.

Heads up: we haven't yet measured the impact of this component, so there are no adoption or performance numbers on this page. We'll add them once we have real data.
