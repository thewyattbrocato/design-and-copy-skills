dotenv-diff

A small command-line tool that compares two .env files and shows which keys are missing, extra or changed. Values are masked by default, so the output is safe to paste into a ticket.

  • Node CLI
  • Values masked by default
  • Exits 1 if any key is missing
  • MIT license
$ npm install -g dotenv-diff
Read the code

Why I made it

Keeping .env and .env.example in sync by eye is easy to get wrong, and a missing key usually shows up as a runtime error later. I wanted a quick check that tells me what drifted without printing my secrets to the terminal.

Usage

Pass the two files to compare. Both are plain arguments:

$ dotenv-diff .env .env.example

Each difference is reported as one of three kinds:

  • Missing: the key is in the second file but not the first.
  • Extra: the key is in the first file but not the second.
  • Changed: the key is in both, but the values differ.

Options

FlagWhat it does
--show-valuesReveal values. Without it, values are masked.
--ignore KEY1,KEY2Skip the listed keys, comma-separated.
--jsonPrint machine-readable output instead of the human-readable report.
 
$ dotenv-diff .env .env.example --ignore DEBUG,NODE_ENV --json

Fail a build when a key is missing

The exit code is 1 if any key is missing, so the command can gate a script or CI step without parsing output. Add --json if you want to read the details in another tool.

$ dotenv-diff .env .env.example || echo "env files are out of sync"

Limits

  • It compares exactly two files per run.
  • It reports differences between the files; it does not edit either one.
  • The exit code reflects missing keys. Extra and changed keys are reported in the output.

Try it

$ npm install -g dotenv-diff
$ dotenv-diff .env .env.example
