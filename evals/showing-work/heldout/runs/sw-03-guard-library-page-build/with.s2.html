See what's different between two .env files.

dotenv-diff is a small Node CLI that compares two env files and shows which keys are missing, extra or changed. Values are masked by default, so the output is safer to paste into a terminal log or a chat.

$ npm install -g dotenv-diff
Read the usage View on GitHub

Install

Install it globally with npm:

npm install -g dotenv-diff

It's a Node command-line tool, so you need Node.js and npm installed.

Usage

Pass the two files you want to compare:

dotenv-diff .env .env.example

The report lists keys that are missing, extra or changed between the files. Values stay masked unless you ask for them.

Illustrative output

$ dotenv-diff .env .env.example
missing  STRIPE_SECRET_KEY
extra    DEBUG_SQL
changed  DATABASE_URL  (values differ: ********)

This sample shows the idea only. The exact formatting of the real output may differ, so run the tool on your own files to see it.

Common recipes

# reveal the actual values
dotenv-diff .env .env.example --show-values

# skip keys you expect to differ
dotenv-diff .env .env.example --ignore NODE_ENV,PORT

# machine-readable output
dotenv-diff .env .env.example --json

What it does

  • Finds missing, extra and changed keys between two env files.
  • Masks values by default. Use --show-values only when you want to see them.
  • Ignores keys you choose with --ignore.
  • Outputs JSON with --json for scripts and tooling.
  • Sets an exit code you can use to fail a check when a key is missing.

Options

FlagWhat it does
--show-values Reveal values in the output. They are masked by default.
--ignore KEY1,KEY2 Skip the listed keys. Separate multiple keys with commas.
--json Print machine-readable JSON instead of the human-readable report.

Exit codes

The process exits with 1 if any key is missing. Otherwise it exits normally. That makes it easy to use in a script or CI step:

# fails the step if .env.example has keys your .env lacks, or the reverse as defined by the tool
dotenv-diff .env .env.example || echo "env files are out of sync"

Extra or changed keys alone don't trigger exit code 1. Only missing keys do.
