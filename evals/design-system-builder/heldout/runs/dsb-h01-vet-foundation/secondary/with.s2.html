Shared tokens and components

Every screen in the web app is built from the values and pieces below. If a value is not on this page, it does not get added to a screen. It gets added here first.

Color

Colors are named by role, not by hue. Use --color-primary for "this is the main action," never a raw hex value. Status colors always come as a text and background pair so they keep 4.5:1 contrast.

Rules for building screens

  1. Use tokens only. No raw hex values, pixel spacing, or font sizes in screen code.
  2. Every interactive element gets a visible focus ring. Do not remove outlines without a replacement.
  3. Touch targets are at least 44px tall.
  4. Every input has a visible label. Placeholder text is never the label.
  5. Errors state what went wrong and how to fix it, with the message tied to its field.
  6. Status is never conveyed by color alone. Pair it with a word or an icon.
  7. Destructive actions use the danger role and ask for confirmation. Primary actions are one per view.
  8. If a pattern is needed twice, it becomes a component here before it appears on a second screen.

Status messages

Use one status message per decision point. Say what happened, then what to do next.

Appointment confirmed Biscuit's visit is booked for November 4 at 9:30 AM. A reminder will arrive 24 hours before.
Vaccine due soon Miso's rabies booster is due in 14 days. Book now to stay on schedule.
Clinic closed Monday For holiday hours, call the front desk. Urgent after-hours care is listed on the contact page.
