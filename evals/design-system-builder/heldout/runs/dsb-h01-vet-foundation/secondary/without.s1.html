Buttons

One primary action per view. Secondary for alternatives. Quiet for low-emphasis actions like cancel or view details.

Rules for building new screens

  1. Use tokens (var(--color-…), var(--space-…), var(--text-…)). Never hard-code colors, font sizes, or spacing.
  2. Start from an existing component. Build a new one only when none fits, and add it to this page first.
  3. One primary button per view. Destructive actions use the quiet or secondary style, with a confirmation step.
  4. Every input has a visible label. Hints and errors connect with aria-describedby.
  5. Show errors as text next to the field. Never rely on color alone.
  6. Use role="status" for confirmations and role="alert" only for errors that need immediate attention.
  7. Write plain, warm sentences. Say what happened and what the person can do next. Avoid jargon and exclamation marks.
