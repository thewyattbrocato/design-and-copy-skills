Hollowbrook Vet Care · Design foundation v1

One set of decisions, used everywhere.

Calm, warm and clear. Every screen (booking, pet records, reminders) is built from the tokens and components below. If you need something that isn't here, adapt an existing piece first; if a second screen needs it, it joins the system.

Assumes one brand, a web product and a small team. Colors are proposals, so confirm them against the real brand.

Principles

  • Trustworthy before friendly. People book care and read health records here. Warmth comes from color, wording and rounded corners. Layout and controls stay conventional.
  • Status is never color alone. Every status pairs color with an icon and a word.
  • Components read roles, not raw values. Use --color-text-secondary, never a hex or --ref-*. This is what lets dark mode and future themes work.
  • 44px minimum targets, visible focus, keyboard first. Many users book from a phone, in a waiting room.

Foundation

Tiers

--ref-* raw values → --color-*, --type-* semantic roles (themes remap these) → components. Components never skip a tier.

How this changes

  • One source. These custom properties are the source. Any design file mirrors them; if they differ, that’s a bug to fix, not a note.
  • New value? Reuse the nearest existing step first. Add a token only when two screens need it, and name it by role (--color-text-secondary), never by color or page.
  • New component? It joins when a second screen needs it. Specify every state, long and empty content, keyboard and focus before merging.
  • Four change types: add, modify, deprecate, remove. Deprecate with a note and a migration before removing. Record each change in a changelog and name an owner. [owner: to be assigned by the team]
  • Every theme checks every text pair. Light and dark are done here; pairs were chosen for strong contrast but should be re-verified with a tool once brand colors are final.
