Restoring a snapshot

Bring files back from any point in your backup history, whether that's a single deleted config file or an entire home directory.

Applies to Brine 2.x · About 5 minutes

Every time you run brine backup, Brine records a snapshot: an immutable view of your files at that moment. Restoring reads the snapshot from your repository, decrypts it, and writes the files you ask for to disk. You don't need the original machine, only the repository location and its password.

This guide assumes you've already created a backup and that BRINE_REPO and BRINE_PASSWORD_FILE are set. If not, add --repo to each command below.

Restore a snapshot

  1. Find the snapshot you want

    List the snapshots in your repository. Newest are shown last.

    $ brine snapshots --host laptop
ID        TIME                 HOST    PATHS         SIZE
3b91c0d4  2026-10-12 02:00:04  laptop  /home/sam     48.2 GiB
7f3a9c2e  2026-10-13 02:00:03  laptop  /home/sam     48.4 GiB
e5d21a87  2026-10-14 02:00:05  laptop  /home/sam     48.4 GiB

  2. Check what's inside

    Browse the snapshot's contents before restoring, so you know you have the right one. Use latest instead of an ID to pick the most recent.

    $ brine ls 7f3a9c2e /home/sam/projects/site
/home/sam/projects/site/config.toml     2.1 KiB
/home/sam/projects/site/content/          -
/home/sam/projects/site/public/           -

  3. Do a dry run

    Add --dry-run to see exactly which files would be written, without touching the disk. Restore to a new, empty directory with --target.

    $ brine restore 7f3a9c2e \
    --include /home/sam/projects/site \
    --target ~/restored \
    --dry-run
would restore 1,284 files (312.6 MiB) to /home/sam/restored
0 files would be overwritten

  4. Restore and verify

    Run the same command without --dry-run. Adding --verify re-reads each written file and checks it against the snapshot's checksums.

    $ brine restore 7f3a9c2e \
    --include /home/sam/projects/site \
    --target ~/restored \
    --verify
restoring  [==============================] 100%  312.6 MiB
verified 1,284 files, 0 errors
snapshot 7f3a9c2e restored to /home/sam/restored
Restoring over existing files can destroy newer work

If you set --target / or point at a directory that already contains files, Brine skips any file that differs from the snapshot unless you pass --overwrite. With that flag, the current version is replaced and cannot be recovered from Brine unless an earlier snapshot contains it.

Restore to an empty directory first, compare, then copy over what you need. Always run with --dry-run before using --overwrite.
