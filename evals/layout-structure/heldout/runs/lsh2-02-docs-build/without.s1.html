Restoring a snapshot

A snapshot is only useful if you can get your files back. This page walks through finding the right snapshot, previewing what a restore will do, and writing the files back to disk.

Before you begin
  • Brine 2.4 or later is installed and your repository is configured.
  • You have the repository password, or BRINE_PASSWORD is set in your environment.

Steps

  1. Find the snapshot you want

    List the snapshots in your repository. Each one has a short ID you can use in later commands. Use --path to filter to snapshots that include a particular directory.

    $ brine snapshots --path ~/Documents
ID        Taken                Host       Paths
a3f91c02  2026-10-12 02:00:04  laptop     /Users/sam/Documents
7be4d810  2026-10-13 02:00:03  laptop     /Users/sam/Documents
c10e5a77  2026-10-14 02:00:05  laptop     /Users/sam/Documents

  2. Preview the restore

    Run the restore with --dry-run first. Brine reports which files would be written or overwritten without touching anything on disk.

    $ brine restore 7be4d810 --target ~/restored --dry-run
Would restore 1,284 files (3.2 GiB) to /Users/sam/restored
  new:        1,284
  overwrite:      0
  unchanged:      0

  3. Run the restore

    Remove --dry-run to restore for real. Restoring to an empty directory with --target is the safest option, since nothing already on disk can be replaced.

    $ brine restore 7be4d810 --target ~/restored
Enter repository password:
[################################] 100%  3.2 GiB  41 MiB/s
Restored 1,284 files to /Users/sam/restored in 1m18s

  4. Restore only what you need

    To recover a single file or folder, pass one or more --include patterns. Paths are matched relative to the snapshot root.

    $ brine restore 7be4d810 --target ~/restored \
    --include "Documents/taxes/2025/**"
Restored 37 files to /Users/sam/restored in 2s
⚠ Restoring over existing files

If you omit --target, Brine restores to the original paths and replaces any files that already exist there with the snapshot's version. Changes made since the snapshot was taken will be lost, and this can't be undone.

Always run with --dry-run first and check the overwrite count. To keep your current files, restore to a separate directory with --target and copy across what you need.
