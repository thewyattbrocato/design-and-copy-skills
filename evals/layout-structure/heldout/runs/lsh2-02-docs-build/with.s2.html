Restoring a snapshot

Bring files back from any point in your backup history, whether that's a single deleted document or an entire home directory.

Every time you run brine backup, Brine records a snapshot: a point-in-time view of the files you backed up. Restoring reads that view from your repository, decrypts it, and writes the files to a location you choose. This page walks through a safe restore from start to finish.

Before you begin
  • Brine 2.0 or later installed on the machine you're restoring to.
  • Access to the repository and its password.
  • Free disk space at least as large as the data you're restoring.

Restore a snapshot

  1. Find the snapshot you want

    List the snapshots in your repository. Each has a short ID, a timestamp, and the paths it contains. Use --path to narrow the list.

    $ brine snapshots list --repo ~/brine-repo
ID        TIME                 HOST       PATHS
7f3a9c1e  2026-10-26 02:00:04  laptop     /Users/sam
b2d84e07  2026-10-25 02:00:03  laptop     /Users/sam
e19c5a62  2026-10-24 02:00:05  laptop     /Users/sam
3 snapshots

  2. Preview the restore with a dry run

    Add --dry-run to see what Brine would write without touching the disk. Check that the file count and size look right.

    $ brine restore 7f3a9c1e --target ~/restore --dry-run
Would restore 18,342 files (4.7 GiB) to /Users/sam/restore
0 files would be overwritten

  3. Run the restore

    Run the same command without --dry-run. To restore only part of a snapshot, pass one or more --include patterns.

    $ brine restore 7f3a9c1e --target ~/restore --include "Documents/**"
Restoring snapshot 7f3a9c1e...
[##########################] 100%  2,914 files  612 MiB
Restore complete in 38s

  4. Verify the result

    Compare the restored files against the snapshot's checksums. Brine exits with status 0 if everything matches.

    $ brine verify --snapshot 7f3a9c1e --against ~/restore
Checked 2,914 files: 2,914 ok, 0 changed, 0 missing
Warning: restoring over existing files

By default, Brine refuses to restore into a folder that already contains files with the same names. If you pass --overwrite, those files are replaced with the snapshot's versions and cannot be recovered afterwards.

Restore to an empty folder first, then copy across only what you need. If you must overwrite, run with --dry-run and read the "would be overwritten" count before continuing.
