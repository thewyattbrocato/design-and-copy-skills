Restoring a snapshot

Last updated 2 September 2026 · 5 min read

A snapshot is only useful if you can get your files back out of it. This page shows how to find the snapshot you want, preview a restore, and write the files to disk, either in full or just the parts you need.

You'll need the path to your repository and its password. The examples assume the repository lives at ~/backups/brine-repo. If you set the BRINE_REPO environment variable, you can leave out the --repo flag in every command below.

Restore from a snapshot

  1. List the available snapshots

    Each snapshot has a short ID, a timestamp, and the host it was taken on. Find the one closest to the point in time you want.

    $ brine snapshots --repo ~/backups/brine-repo
ID        TIME                 HOST       PATHS
4f9c2a1e  2026-09-01 02:00:04  laptop     /Users/sam
b81d07c3  2026-08-31 02:00:03  laptop     /Users/sam
e07a55d9  2026-08-30 02:00:05  laptop     /Users/sam
3 snapshots

  2. Inspect its contents

    Use brine ls to confirm the snapshot contains the files you expect. Add a path to narrow the listing.

    $ brine ls 4f9c2a1e /Users/sam/Documents --repo ~/backups/brine-repo
/Users/sam/Documents/budget-2026.xlsx
/Users/sam/Documents/notes/ideas.md
/Users/sam/Documents/notes/travel.md
/Users/sam/Documents/thesis/draft-v7.docx

  3. Preview the restore with a dry run

    A dry run reports what would be written without touching the disk. Point --target at a directory that doesn't exist yet.

    $ brine restore 4f9c2a1e --target ~/restored --dry-run --repo ~/backups/brine-repo
would restore 1,284 files (3.2 GiB) to /Users/sam/restored
0 files would be overwritten

  4. Run the restore and verify it

    Drop --dry-run to write the files. To restore only part of the snapshot, add one or more --include patterns. Then check the result against the stored checksums.

    $ brine restore 4f9c2a1e --target ~/restored --include "Documents/**" --repo ~/backups/brine-repo
restoring  [==============================]  100%  412 files
done in 18s

$ brine verify --restored ~/restored --repo ~/backups/brine-repo
412 files checked, 0 mismatches
Warning: restoring over existing files

If you restore directly into the original location, Brine will replace files that have the same path. Any changes made since the snapshot was taken are lost, and this can't be undone.

By default, brine restore stops if the target directory isn't empty. Passing --overwrite turns that check off. Restore to a fresh directory first, compare the results, and then copy across only what you need.
