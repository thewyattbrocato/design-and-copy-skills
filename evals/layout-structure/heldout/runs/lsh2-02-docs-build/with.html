Backups / Restoring a snapshot

Restoring a snapshot

A snapshot is only useful if you can get your files back. This page walks through finding the right snapshot, previewing what a restore will do, and bringing files back, either to a safe location or over the originals.

About 5 minutes Requires Brine 2.2 or later Updated 2 September 2026

You'll need a configured repository with at least one snapshot. If you haven't made one yet, start with Creating a backup. The examples use a repository at /mnt/backup/brine; substitute your own.

Restore a snapshot

  1. Find the snapshot you want

    List the snapshots in your repository. Each one has a short ID, a timestamp, and the paths it covers. Add --path to narrow the list to one directory.

    Terminal
    $ brine snapshots --repo /mnt/backup/brine --path ~/Documents
ID        Time                 Host       Paths
a41f9c2   2026-09-28 02:00     laptop     /Users/sam/Documents
7be03d8   2026-09-27 02:00     laptop     /Users/sam/Documents
c9d1e45   2026-09-26 02:00     laptop     /Users/sam/Documents
3 snapshots

  2. Preview the restore with a dry run

    Pass --dry-run to see which files Brine would write, without touching anything on disk. Use --include to restore only part of a snapshot.

    Terminal
    $ brine restore a41f9c2 --repo /mnt/backup/brine \
    --include "Documents/Taxes/**" \
    --target ~/restore-test --dry-run
would restore  Documents/Taxes/2025-return.pdf   (1.4 MiB)
would restore  Documents/Taxes/receipts.zip      (86.2 MiB)
2 files, 87.6 MiB. No changes made.

  3. Restore to a separate folder

    Run the same command without --dry-run. Restoring to a new --target directory is the safest option, because your current files stay exactly as they are while you check the result.

    Terminal
    $ brine restore a41f9c2 --repo /mnt/backup/brine \
    --include "Documents/Taxes/**" \
    --target ~/restore-test
restoring  [==============================]  100%  87.6 MiB
Restored 2 files to /Users/sam/restore-test

  4. Verify the restored files

    Compare the restored copy against the snapshot. brine diff reports any file that is missing or whose contents differ. No output besides the summary means everything matches.

    Terminal
    $ brine diff a41f9c2 ~/restore-test --repo /mnt/backup/brine \
    --include "Documents/Taxes/**"
0 differences. 2 files checked.
⚠ Warning: restoring over existing files

If you set --target to the original location (or use --in-place), Brine overwrites any file with the same name. Changes you made after the snapshot was taken are lost, and Brine does not keep a copy of the replaced files.

Run with --dry-run first. To keep what's on disk, add --no-overwrite, which skips files that already exist.
