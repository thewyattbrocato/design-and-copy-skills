Restoring a snapshot

Every backup Brine makes is stored as a snapshot. This page shows how to find the one you want, check what’s in it, and bring back some or all of its files.

About 5 minutes Requires Brine 2.0 or later Updated 14 October 2026

Restoring never changes the snapshot itself, so you can run it as often as you like. By default Brine writes files to a location you choose and leaves everything already on disk alone. The steps below use that safe default, and the warning after them covers the exception.

Restore in four steps

  1. List your snapshots

    Each snapshot has a short ID, a timestamp and the paths it covers. Newest comes first.

    $ brine snapshots list
ID        TIME                 HOST       PATHS
7f3a9c1e  2026-10-26 02:00:04  mbp-robin  ~/Documents, ~/Projects
b91d04aa  2026-10-25 02:00:03  mbp-robin  ~/Documents, ~/Projects
2c58e7f0  2026-10-24 02:00:05  mbp-robin  ~/Documents, ~/Projects

  2. Inspect the one you want

    Use show to see the file tree and size. Add --path to look inside a single folder.

    $ brine snapshots show 7f3a9c1e --path ~/Documents
Snapshot 7f3a9c1e · 2026-10-26 02:00:04 · 41,208 files · 12.4 GiB
Documents/
  Invoices/    (212 files)
  Notes/       (1,046 files)
  Taxes/       (88 files)

  3. Preview with a dry run

    Add --dry-run to see what would be written without touching the disk. Point --target at an empty folder so nothing can collide.

    $ brine restore 7f3a9c1e --target ~/brine-restore --include "Documents/Taxes/**" --dry-run
Would restore 88 files (310 MiB) to /Users/robin/brine-restore
0 conflicts. No changes made.

  4. Run the restore

    Remove --dry-run. Brine verifies each file against its checksum as it writes, and exits with a non‑zero code if any check fails.

    $ brine restore 7f3a9c1e --target ~/brine-restore --include "Documents/Taxes/**"
Restoring  88/88 files  310 MiB  [##########] 100%
Verified 88 files. Restore complete in 6.2s.
Restoring over existing files can destroy newer work

If you set --target to the original location and pass --on-conflict overwrite, Brine replaces any file that already exists with the snapshot’s version. Changes made since the backup are lost and can’t be undone. Run a dry run first, or restore to a separate folder and copy files across by hand. The default, --on-conflict skip, never overwrites.
