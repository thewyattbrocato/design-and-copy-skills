Backups / Restoring a snapshot

Restoring a snapshot

A snapshot is only useful if you can get your files back. Brine restores a whole snapshot, a single folder, or one file, to the original location or anywhere else you choose.

This page walks through a typical restore from the command line. It assumes you have already created a backup and that your repository is reachable. Most restores take under a minute for small folders; large snapshots are limited mainly by your network and disk speed.

Time: about 5 minutesRequires: Brine 2.0 or laterUpdated: October 2026

  1. List the snapshots in your repository

    Find the snapshot you want. Each one has a short ID, a timestamp, and the host it came from.

    $ brine snapshots --repo ~/brine-repo
ID        TIME                 HOST       PATHS
a3f91c0e  2026-10-12 02:00:04  laptop     /Users/sam
7be2d418  2026-10-13 02:00:03  laptop     /Users/sam
c05a77f2  2026-10-14 02:00:05  laptop     /Users/sam

    Use latest in place of an ID to refer to the most recent snapshot.

  2. Preview what the snapshot contains

    Browse the file tree before you restore, so you know the paths you need. Add a path to narrow the listing.

    $ brine ls c05a77f2 /Users/sam/Documents
/Users/sam/Documents/budget-2026.xlsx
/Users/sam/Documents/notes/ideas.md
/Users/sam/Documents/notes/todo.md
3 files, 1.2 MiB

  3. Run a dry-run restore

    Restore to a new, empty folder first. With --dry-run, Brine reports what it would write and changes nothing on disk.

    $ brine restore c05a77f2 \
    --repo ~/brine-repo \
    --target ~/restore-test \
    --include "/Users/sam/Documents" \
    --dry-run
would restore 3 files (1.2 MiB) to /Users/sam/restore-test

  4. Restore and verify

    Remove --dry-run and add --verify. Brine re-reads each restored file and compares its checksum with the one stored in the snapshot.

    $ brine restore c05a77f2 \
    --repo ~/brine-repo \
    --target ~/restore-test \
    --include "/Users/sam/Documents" \
    --verify
restoring  3/3 files  [####################]  100%
verified 3 files, 0 errors
Restoring over existing files

If you set --target to a folder that already holds files, or to /, Brine overwrites any file with the same path. Changes made since the snapshot are lost and can't be undone.

To be safe, restore to an empty folder and copy files across by hand. If you do need to restore in place, add --keep-newer to skip files modified after the snapshot was taken.
