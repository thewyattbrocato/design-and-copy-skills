Restoring a snapshot

Bring back a single file, a folder, or an entire machine from any snapshot Brine has stored. Restores are read-only against your repository, so you can try them as often as you like.

Updated 14 October 2026 · About 5 minutes · Requires Brine 2.2 or later

A snapshot is a point-in-time record of everything a backup run captured. To restore, you pick a snapshot, choose where the files should go, and let Brine fetch and decrypt only the data you ask for. You will need your repository password, and network access if the repository is remote.

The steps below restore the ~/Documents/invoices folder from last Tuesday's backup into a scratch directory. The same flow works for whole snapshots.

Restore steps

  1. Find the snapshot you want

    List what is in the repository. Each snapshot has a short ID, a timestamp, and the paths it covers.

    $ brine snapshots list
ID        Time                  Host       Paths
a41f9c02  2026-10-20 02:00:07   laptop     /Users/sam
7be3d150  2026-10-21 02:00:11   laptop     /Users/sam
c90a27e8  2026-10-22 02:00:09   laptop     /Users/sam
3 snapshots

  2. Check what the snapshot contains

    Browse the snapshot's file tree to confirm the path you need is there. Nothing is downloaded at this point.

    $ brine ls 7be3d150 /Users/sam/Documents/invoices
/Users/sam/Documents/invoices/2026-08.pdf
/Users/sam/Documents/invoices/2026-09.pdf
/Users/sam/Documents/invoices/2026-10-draft.pdf

  3. Preview the restore with a dry run

    Add --dry-run to see exactly which files would be written, replaced, or skipped. Set --target to a new, empty directory to keep restored files apart from your live ones.

    $ brine restore 7be3d150 \
    --include /Users/sam/Documents/invoices \
    --target ~/brine-restore \
    --dry-run
Would restore 3 files (4.2 MiB) to /Users/sam/brine-restore
0 files would be overwritten
Restoring over existing files can destroy newer work

If --target points at a folder that already holds files, Brine replaces any file whose name matches, even if your current copy is newer than the snapshot. Replaced files are not recoverable from Brine.

Restore to an empty directory first, then copy across what you need. If you must restore in place, run with --dry-run first and add --no-overwrite to skip files that already exist.

  1. Run the restore and verify it

    Drop --dry-run and add --verify. Brine re-reads each restored file and compares its checksum with the one stored in the snapshot.

    $ brine restore 7be3d150 \
    --include /Users/sam/Documents/invoices \
    --target ~/brine-restore \
    --verify
restoring  3/3 files  4.2 MiB  done in 2.1s
verified   3/3 files  checksums match

    A non-zero exit code means something failed. See Exit codes for what each one means.
