# Honest claims

Copy that states a fact or makes a promise needs a true basis, and the strongest true version usually persuades better than an inflated one. The default failure is invention: a count, a quote, a rating, a deadline or a study that nobody supplied. The opposite failure is hedging until nothing is left. Keep the force of what is true, and add nothing else.

## Do not produce

- A number, name, quote, rating, logo, award, press mention or study result the user did not give.
- "Studies show", "experts agree" or "trusted by thousands" with no source behind it.
- A countdown, "only N left", "ends soon" or "reserved for you" with no real cause the user gave.
- A "was" price that was never charged, or a "value" for something never sold.
- "Guaranteed" with no condition and no remedy.
- A mild extra the facts do not carry ("no contract", "cancel anytime", "still warm", "every one of them") when the sheet is silent.
- The opposite claim to fill a gap ("plenty of seats left", "no rush") when nothing says it.

## When to use

- Writing, rewriting or reviewing copy that contains facts, figures, proof, comparisons, prices, guarantees, deadlines or limits.
- Requests to make copy more credible, urgent, scarier or "more official", or to write reviews, quotes, counts or statistics.
- A page or draft to check for claims that could mislead or draw a complaint.
- Any other copy task, as a last pass on what the draft asserts.

## When not to use

- Defaults, pre-ticked options, decoy tiers, cancellation flows and how much fear to apply: fair-persuasion, if installed. This skill checks only the words those flows use.
- Line editing for length, rhythm or tone: editing-and-cutting, if installed. Offer structure, whole pages and positioning: the matching copy skill, if installed; otherwise apply the rules below.
- Legal review. Flag the risky category in one line ("have this checked"); do not interpret law.
- Fiction, satire and clearly labelled mock data: invention is correct there, so add no disclaimers.
- Plain statements of what a product does need no proof.

The user's wording and voice win over every default here, except where a line would state something false. "The client asked" does not change that.

## When facts are missing

Do the work anyway. Ask once, in one short list with a default for each item, only if the session is interactive and the answer is cheap; never reply with only questions. Otherwise use what was given, put a short bracketed placeholder where proof matters (`[customer quote]`, `[source for this figure]`), and write the strongest sentence that stays true without it. Placeholders hold no invented content, appear only where proof is worth getting (about one per section) and need no reminder paragraph. Cut decoration like "industry-leading" instead of marking it. If the user insists on invented proof, give one line of reason and deliver the honest version that does the same job.

## Rules

- **Scope every number.** Keep its basis, date and conditions ("in our tests", "as of May"). Round down, never up, and never make a figure more exact than the evidence. Keep every true qualifier ("typical", "weekdays"); drop one only if the user's evidence supports the flat claim.
- **A measured result is not a cause.** What happened after the product is not what the product did. Write the measurement, or "we think", unless the user states the cause.
- **Typical, not best.** Show the typical result; label an exceptional one as exceptional, with the typical range if known.
- **Quotes** are the user's words, trimmed, never reworded, spliced or composed. If asked to write testimonials, give a short request message to real customers plus placeholders.
- **Urgency** only with a real cause and exact end the user gave; state both, plainly and confidently. Otherwise lead with the real benefit or the true cost of waiting. A timer that resets, a rolling end date or a banner that never changes is decoration.
- **Counts and "most popular"** only from data, with basis and date; a perfect rating reads as fake, so show the sample. With none, use true growth, a softer true label, or no proof line. Never present a bad habit as the norm; say what people like the reader do, or name the step.
- **Comparisons** use real alternatives on one dimension, dated, crediting a rival where it wins. Do not name or characterize a rival without a fact the user gave; with none, state the differentiator without naming anyone, or ask for the checkable fact when interactive.
- **Fear** needs a documented risk at true scale beside a step the reader can take now. No invented statistic, no shame, no hint of a cover-up.
- **Terms sit beside the claim** at similar weight: "free", trials, renewals, fees, "was" prices, and guarantees stated as condition and remedy ("if X has not happened by Y, we Z"). A condition in fine print or a tooltip does not count.
- **Plain mechanism.** Describe how it really works; do not invent an ingredient or method to make a promise feel new, borrow the look of news or official mail, or tease with no payoff.
- **Candor is persuasive.** A stated limit, a true reason for a price, or a demo the reader can repeat often beats a superlative.

## If the text already works

If a line is true and effective, say so and change at most a word. Do not rewrite supported claims into weaker ones, and do not rewrite for taste. Fix only what is unsupported.

## Output

Deliver the requested text first, with nothing before it. When a count or a set is asked for (three lines, five options, a banner), deliver exactly that, and check the count and any length cap against the text before handing back; do not assert them. Add at most two one-line notes, only for what the user must act on: a placeholder to fill, an assumption, a high-risk claim to have checked. No explanation of every change, no claim table or checklist unless asked. Answer in the user's language, placeholders included.

## Judgment calls

- **Strength.** Default to the strongest true claim, not the safest. Change for health, money, safety and children: state limits plainly there.
- **User-supplied facts.** Default to using them as given, with their scope. Change for high-risk categories (health outcomes, earnings, "guaranteed", "#1", "only", "first", environmental, named rivals): use them, plus one line to have the claim checked.
- **Proof source.** Default to outside proof (a customer, a test, a third party) over the seller's say-so. Outcome, rank and rival claims need a basis; descriptions do not.
- **Urgency.** Default to none. A real deadline is good copy; use it.

## Common failures

- A proof line with an invented count → a dated real count, a placeholder, or none.
- "Industry-leading", "#1", "best" → what it does, measured if known.
- "Satisfaction guaranteed" → condition, remedy, how to claim.
- A result presented as caused by a method the user never credited → the measurement, or "we think".
- A quote polished into brand voice → their words, trimmed only.
- Notes that explain every edit, or a compliance list on a short request → two lines at most.
- A comparison table the product wins on every row → real rivals, same rows, their strengths shown.
- Everything hedged → restore the strong true claims; soften only the unsupported ones.

## Quick checks

- Every number, name, quote and rating is in the brief or is a visible placeholder; nothing extra was added.
- Every deadline, limit and "most popular" has the cause the user gave.
- Terms and conditions are beside the claims they qualify.
- Supported claims stayed strong, and the copy would ship once placeholders are filled.
- Counts and length caps verified, not asserted.
