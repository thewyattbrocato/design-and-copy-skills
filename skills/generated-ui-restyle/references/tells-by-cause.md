# Tells by cause

Load when diagnosing a screen, and before writing the decision notes. A generated look comes from a handful of habits, each with a cause. The cause tells you what goes in the tell's place; removing tells one by one without it leaves an emptier version of the same template.

A mark is a tell only when it has no job. The same device is a decision in one product and a leftover in another: a gradient written into a brand guide, capitals in an established label system, a pulse on a count that really is live. Check before listing.

Report one line per tell with its place, and fold repeats into one line with a count: "`.plan-card` (all three): accent-colored glow under each card, cause 1".

## 1. Light added to look finished

The screen borrows polish from effects instead of from choices. Typical forms: a blend between two hues used as a fill for the page, a button or the current menu item; headline or total text clipped to a gradient; a glow tinted with the accent, so the accent ends up everywhere; blurred color drifting behind the content; translucent panels with bright rims stacked over a colored ground.

What replaces it: a plain ground, depth shown by small lightness steps and hairlines, and color moved to the content that answers the screen's main question (visual-hierarchy). Owners: visual-hierarchy (the job test in decoration and depth), color-palette (gradients only with a job).

## 2. Starting values left in place

The tool's or kit's defaults are still there, so the screen matches every other screen started from them. Typical forms: an indigo or violet that nobody at the company chose; the framework's default face; one large radius applied to everything from inputs to the page frame; the centered stack and the heading-plus-three-cards row that layout-structure calls the stock template; an icon in a tinted circle above every feature title (visual-hierarchy's do-not list).

What replaces it: a choice the decision notes can source. An accent drawn from the product's own subject, a face that suits how the product should sound, radii that grow with the element, an arrangement that shows how the content relates. Owners: color-palette, typeface-selection, layout-structure.

## 3. Numbers written line by line

Each value was typed when its line was written, so nothing agrees. Typical forms: paddings and gaps off any scale (spacing-and-grouping's 22s and 37s); menu items that are not the same height; labels that start on different vertical lines because their icons differ in width; more type sizes than the content has levels; dates written two ways, percentages with and without decimals, a currency symbol on some totals only.

What replaces it: one spacing scale, one height per list, one format for each kind of figure with tabular digits. Owners: spacing-and-grouping, typesetting.

## 4. Everything turned up

When every element asks for attention, none gets it. Typical forms: the heaviest weight on every heading; tiny labels spaced out in capitals; colored pills around plain counts; tags such as "hot" or a plan tier sprinkled over menu items; emoji used as the icon set, inside counts and as status; three accents in one view; several buttons of equal weight where one action matters.

What replaces it: a ranked order with one focal point per view, one primary action per decision, meta as quiet text in sentence case, and one accent kept small. Owners: visual-hierarchy, typesetting.

## 5. Words and data that fit any product

The text and sample content would read the same on a rival's screen. Typical forms: a welcome message where the screen's name should be; stock enthusiasm and exclamation marks (editing-and-cutting's template voice); verbs of transformation and vague superlatives where the product's actual result should be; figures with no context, no prior period or target (chart-design); sample numbers that look typed, such as sequential digits or every value round; unsourced customer counts, ratings or logos (visual-hierarchy's made-up proof).

What replaces it: the product's own nouns, sample data of the right shape and spread, context on every changing figure, and proof the person can stand behind or none. Owners: ux-microcopy, headlines-and-leads, editing-and-cutting, honest-claims, chart-design.

## 6. Pictures that stand for a category

The image says "technology" or "growth" rather than showing this product. Typical forms: an abstract render with no subject; a mascot or symbol for automation; a stock illustration of people around an oversized device; a picture on every section because sections "need" one; words set inside an image, where they cannot be read aloud, resized or translated.

What replaces it: the product itself, rendered in HTML and CSS at the moment the headline describes, with believable data; a real picture the person supplies; or a sized, labeled placeholder. Usually one picture, where it helps most. Owner: visual-hierarchy (illustration and imagery); see [components and details](components-and-details.md).

## 7. Motion for its own sake

Typical forms, in ui-motion's terms: a call to action that pulses forever; decoration that floats or shimmers in a loop; hover effects on things that cannot be clicked; `transition: all`; overshoot on simple controls; every section fading up on scroll.

What replaces it: motion that confirms an action or shows where something came from, quick and interruptible, and no loop unless the thing it marks is live. Owner: ui-motion.

## 8. After the passes: removed but not replaced

This is a check on your own result, not a tell in the original. A restyle that only removes lands on the kit's own demo look: correct, neutral and nobody's. If a rival's name fits on the result unchanged, the sources were too thin: go back for more of the product's own nouns rather than adding an effect.

## Reading the spread

Note which causes show up and where. The spread explains the size of the change in a diagnosis; the size of the job itself follows the request (see Scope the job in the skill).
