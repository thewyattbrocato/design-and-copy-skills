I won't write the line with 30% in it. There's no data behind that number, so it would be a made-up statistic on a slide presented as a finding. If anyone asks where it came from, you'd have nothing to point to, and that's a bad spot to be in with your VP.

You may still be able to get a real number quickly, even without a baseline.

**Options for a real number (days, not months):**
- **Historical ticket data:** If your helpdesk (Zendesk, Intercom, Jira Service Desk, etc.) has history, compare tickets per active user or customer for the months before and after the docs launched. You don't need a prior measurement plan, just the timestamps.
- **Topic-level comparison:** Pick the 3–5 ticket categories the docs cover and compare their volume to categories the docs don't cover. If the covered ones fell and the rest didn't, that's a credible signal.
- **Docs-to-ticket deflection:** Pull page views on the key docs pages, plus any "was this helpful?" votes. A statement like "X thousand sessions on setup docs last quarter" is real and still persuasive.
- **Quick survey:** Add one question to the ticket form: "Did you check the docs first?" Two weeks of responses gives you a real number going forward.

**Slide lines you can use today, with no fabricated data:**
- "Docs are now the first stop for [X] users per month. Next quarter we're measuring ticket deflection."
- "Baseline established: [N] tickets/month in docs-covered categories. Target: reduce by 20% by Q2."

The second one gives your VP a number, shows the work is being measured, and sets up a real result later.
